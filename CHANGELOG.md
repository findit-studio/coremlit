# Changelog

Notable changes to the crates in this workspace. Versions follow SemVer per crate.

## coremlit 0.1.0 (unreleased)

Initial release: a safe, synchronous CoreML runtime layer.

- `Model`: load / compile / prewarm, synchronous `predict`, eager `ModelDescription` I/O snapshot.
- Stateful prediction via `MLState` (macOS 15+, probed at runtime with `supports_state`).
- `MultiArray`: typed views for `f16`/`f32`/`f64`/`i32`, IOSurface-backed `f16` construction for the Neural Engine, stride-aware `read_at`/`copy_into` for row-padded outputs, index math and scatter fills.
- `Features`: insertion-ordered named I/O bridging `MLFeatureProvider` in both directions (output extraction de-aliases buffers shared with inputs or other outputs).
- Threading: `Model`, `MultiArray`, and `State` are `Send` but deliberately **not** `Sync` — move them between threads or hold one per worker; concurrent shared access is outside the contract.
- `ComputeUnits`/`DataType` vocabularies; structured `thiserror` errors capturing `NSError` domain/code/message.
- `audio::speaker::extract::Extractor::extract_chunk_embeddings` (feature `speaker`): the per-chunk EMBED door, opening the middle node of the `segmentation → embed → cluster` split whose other two ends (`SegmentModel::infer` + `multilabel` + the `window` grid; `count_from_segmentations` + `Extraction::try_from_parts`) were already public. One chunk's audio and its `[f][s]` multilabel slab in; that chunk's `[s][d]` raw-embedding block out, with the slab zeroed in place along both drop paths — i.e. pyannote's `embedding_exclude_overlap` mask derivation, the batched embed call with its placeholder-mask scheme, and the per-row PLDA reachability check, none of which an out-of-crate embed node can write correctly by hand. Additive: `Extractor::extract` keeps its signature and its behaviour, and is now a caller of the same private `embed_chunk_slots` this door runs, so the fused path and the split path cannot drift on a policy this crate parity-gates against dia. Pinned by an equivalence gate that drives 30 s of `ted_60` through the public doors chunk by chunk and rebuilds an `Extraction` BIT-identical (`f32::to_bits`/`f64::to_bits`, not `==`) to the fused `extract`'s. Takes no `SegmentModel` — the split exists so the embed node never loads one — and reads only `Options::window`'s `onset`; the chunk must be exactly `SEG_CHUNK_SAMPLES`, refused with the segmenter's own `InferError::InputLength` rather than padded, because `EmbedModel::embed_chunk` repeat-pads where `extract` zero-pads.
- `audio::speaker::calibrate` (feature `speaker`): the AS-Norm calibration surface (#123 ask 2) — the crate's FIRST **cross-recording** speaker door, and the answer to "raw cosine scores are not comparable across speakers, so a single global threshold over-merges some identities and under-merges others". Everything else in `audio::speaker` is within-recording; this one scores voice profiles at cluster-centroid grain against a library-wide cohort, for binding the same person found in two different recordings. `coremlit` exposes SCORING and never a store: the caller owns the library, the identities and the cohort-selection policy, and hands in a `Cohort` plus the candidates. The AS-Norm1 arithmetic is `diaric::score_norm` CALLED THROUGH, not reimplemented — `CohortStats`, `as_norm`, the `AsNormOptions` defaults and the `MAX_NORMALIZED_ERROR` accuracy postcondition are re-exported so a caller needs no direct `diaric` dependency. What this door adds is the two things between a raw WeSpeaker row and an `f64`: preparation (`Scoring::prepare` on a 256-d row — no existing type changed, `raw_embeddings()` still returns `&[f32]`), and a FALLIBLE boundary, since diaric's cohort statistics take an infallible `FnMut(&S, &T) -> f64` and an `unwrap_or(0.0)` inside that closure poisons a mean silently. **The self-contamination choice stays the caller's**: `cohort_stats_excluding` / `cohort_stats_assuming_disjoint` mirror diaric's two precondition-carrying names and there is deliberately NO convenience that picks one — #123's cohort is sampled from the library being scored, so a speaker's own entries are *guaranteed* into its own top-N (a self-match is the global maximum) and only the caller knows a probe's identity. **Two score sources**, both cosines, differing in the space: `Scoring::Cosine` calls `diaric::embed::cosine_similarity` so a trial score is BIT-identical to what the online clusterer matches on (and to what the offline pipeline's `ahc_init` cuts on, whose Euclidean distance over L2-normalized rows is `sqrt(2 - 2*cos)`); `Scoring::PldaCosine` scores in the frozen community-1 128-d PLDA projection. The second carries a stated honesty boundary — the offline pipeline hands those features to VBx, a set-level EM that emits no trial score, so pairwise cosine in PLDA space is THIS door's construction, characterized and not validated, offered because #123's ask 3 is a comparison between score sources and needs more than one. Mixing sources is a typed refusal (`CalibrateError::ScoringMismatch`) reported ahead of diaric's own `NonFiniteScore`, so a cohort holding one foreign entry is refused rather than averaged. NOT wired into the clustering path (that is within-recording, differently gated) and NOT a threshold — #123's ask 3 produces one, and it needs data this repository does not have. 18 hermetic unit tests over hand-placed unit vectors, five error-Display tests, and two doctests (a runnable end-to-end example, and a `compile_fail` pin that a non-`Eq` speaker key cannot reach `cohort_stats_excluding` — a `NaN` key would not match its own entry and would keep the self-match in). Written red first, and each survivor checked by mutation: an f64-accumulating cosine, a collapsed per-speaker statistic, and a `PldaCosine` that degrades to `Cosine` are each caught. Among them the #123 claim made falsifiable: a fixture where no single RAW threshold separates a genuine trial for an isolated speaker from an impostor trial for a crowded one, and an AS-Norm threshold does.
- `embeddings::siglip` (feature `siglip`): SigLIP 2 (`siglip2-base-patch16-naflex`) image+text embeddings into a shared 768-dim joint space — NaFlex host-side preprocessing (aspect-preserving patch-budget solver, antialiased-bilinear resize, position-embedding lift; no image-decoder dep), a single-input 64-token text tower, and cross-modal `rank`, L2-normalized in Rust; committed transformers-fp32 goldens (no `ort`). Hermetic preprocessing + embedding core landed; model-gated parity gates await the staged conversion.
- `audio::ced` (feature `ced`): CED (tiny/mini/small/base) AudioSet sound-event tagging — 16 kHz mono waveform in, ranked predictions over the 527 rated AudioSet classes out (`soundevents-dataset`, ort-free). Rust log-mel front-end (believed CED numerics, structurally gated; probe-pinned next wave) around one fp16 mel→logits graph; long clips via `windit` window geometry + Mean/Max confidence-space aggregation (soundevents semantics, tie-break pinned), bounded by a default-on `WindowPlan::max_windows` cap that refuses a window-count blow-up in O(1) with a typed `TooManyWindows`/`AllocFailed` before any span or inference is materialized (an untrusted `hop_samples: 1` is a typed refusal, not a panic/OOM) and streamed through a shared accumulator so `classify_long` never holds every window's confidences at once; `raw_scores` logit escape hatch; `DEFAULT_COMPUTE = All` documented PROVISIONAL. The four sizes share one size-invariant mel→logits contract; `CedModel` {Tiny, Mini, Small, Base} carries the HF repo ids and the staged bundle path (`mlmodelc_path`), with serde/`FromStr` snake_case selection. `target_length = 1012` is upstream pos-embed capacity, not the 1001-frame input width (documented + capacity-pinned). Hermetic core landed; per-size model-gated parity/e2e gates and goldens are pre-shaped and await each size's staged conversion.
- `audio::lid` (feature `lid`): native spoken-language identification — 16 kHz mono waveform in, the top `k` of a 107-language roster out (code + English name + model column + natural-log probability). A Rust log-mel front end (`rustfft`) feeds one fp16 mel→log-probabilities graph; the graph's last op is a log-softmax, so no softmax runs in Rust. Deliberately a **backend-neutral door**: nothing in the public surface (`Identifier`, `LanguageScore`, `Language`, the geometry constants, the `LID_TEST_MODELS` env var, the `Models/lid` root) names the model behind it, so a second backend lands without renaming a caller's code; today's backend is an Apache-2.0 CoreML export of `speechbrain/lang-id-voxlingua107-ecapa`. The 107-label roster is a COMMITTED in-crate asset (`include_bytes!`) with a `const` table proven byte-equal to it, preserving upstream's legacy `iw`/`jw` codes so no output column ever shifts (alias folding is a downstream job, and the three facts are pinned). One prediction is capped at 0.09–30.01 s, with anything outside it a typed `FrameCountOutOfRange` refused before CoreML sees it; `identify_long` lifts the ceiling by windowing, keeping `identify`'s contract byte-identical and returning bit-identical results on a clip that already fits one window. The two things a long path has to invent were MEASURED, on two oracles built from the model itself (self-consistency against the single-shot answer, and concatenation of the committed Thai reference), not assumed: window GEOMETRY rides `windit` (fixed 10 s default window — the one frame count `prewarm` warms — a `TailPolicy` that slides the final window BACK to full length rather than padding it, and the same default-on `max_windows` O(1) refusal `ced` carries), while log-probability POOLING is this door's own third domain, neither `ced`'s independent sigmoids nor windit's unit vectors. `ScorePooling` ships all four evaluated candidates — the duration-weighted logarithmic pool (default; best top-1, top-3 and row error at every geometry tried), the linear pool (keeps a mixed clip's minority language, which the default erases), per-class max, and a per-window argmax vote (rejected as default on 36–40 % top-3 agreement) — and the module docs carry the full comparison table, the tail-treatment numbers (zero-padding a tail of 3 s or less CHANGES the reported language, shifting the row by up to 19 nats, which is why there is no `Pad` policy), and an explicit list of what two model-derived oracles do not verify. Fully registered in CI: a `features`-job combo (`lid` alone, plus both all-on rows) runs the hermetic suite on every PR, and a `lid` `model-tests` shard (mirrored in `coverage.yml`) stages the 41 MB bundle from MODELS_LOCK and runs all sixteen model gates. The shard needed two pieces of model-numerics work first, both landed: `tests/fp16_guards.rs`'s MIL reader now takes coremltools 9's bare-scalar dialect (`fp16 v = const()[val = fp16(…)]`) as well as the `tensor<fp16, []>` spelling — the artifact's 36 guard sites resolved to zero before it — and the graph's final `softmax -> log` `epsilon = 0x1p-149` is pinned in `KNOWN_DEFECTS` with a measured note: inert on all four backends today (the fused log-softmax never consults it; 107/107 rows finite, tail to −37.27), armed only by a static-shape re-conversion (105/107 entries would become ANE `log(0)` = −45440, finite, so no guard fires), and NOT repairable by either a healthy fp16 epsilon (ANE flushes subnormals) or an `x − logsumexp(x)` rewrite (fp16 overflow in the reduce) — only by an fp32 island. The artifact repo ships no `CHECKSUMS.sha256` (its digests live in an `artifact_manifest.json` `shasum -c` cannot read), so the shard declares `checksum-dir: none` under a reasoned, staleness-checked `CHECKSUMLESS_KITS` registry, with the exact per-file SHA-256 manifest in `tests/lid/common/mod.rs` standing in.
- Dependencies: `diaric` 0.1 → 0.2, moved in `coremlit` and `coremlit-parity` together — the parity manifest requires ONE shared diaric build (two copies make `Extraction::diarize`'s arguments distinct types), so re-pinning either side alone reds the workspace. The break is diaric's, not this crate's: 0.2 carries the clustering core onto `mediatime` 0.4 (`Timebase` signed — `num: u32 → i32`, `den: NonZeroU32 → NonZeroI32`) and `nalgebra` 0.35, and adds a `score_norm` (AS-Norm1) module left deliberately UNWIRED here; calibration is its own surface (#123). **Nothing in coremlit's own behaviour changes**, and that is checked rather than asserted: diaric's whole `mediatime` surface lives in its `segment` module, which `audio::speaker` never imports, so every value crossing the boundary is scalar (`SlidingWindow` and `RttmSpan` carry `f64` seconds, `min_duration_off` an `f64`) and `audio::speaker` names no `Timestamp`, `Timebase` or `TimeRange` at all — the one line the mediatime major cost diaric is `SAMPLE_RATE_TB` in `segment/options.rs`, and `nalgebra` 0.35 cost it none. Resolved graph: the `mediatime` duplicate does NOT collapse. coremlit's own tree keeps 0.1.9 (`asry`) beside 0.4.0 (now `diaric` as well as `pixon`→`mediaframe`); across the workspace `coremlit-parity`'s unpublished `dia` oracle holds 0.1.9 too, and splits `nalgebra` into 0.35 (`diaric`) and 0.34 (`dia`) — a parity-only split that crosses no type boundary, since no nalgebra type appears in any gate.
- Hygiene: four debts closed. ## whisperkit 0.1.0 (unreleased)

Initial release: a Rust port of [WhisperKit](https://github.com/argmaxinc/WhisperKit) (Swift) on CoreML, sans-I/O (16 kHz mono `&[f32]` in).

- Full pipeline: mel → encoder → autoregressive decoder with prefill prompts, KV caching, logits filters, and the temperature-fallback ladder; token parity with Swift `whisperkit-cli` on `openai_whisper-tiny` (en + es goldens).
- Long-form: energy-VAD chunking (sequential per chunk on the CoreML backend, which is deliberately not `Sync`), seek re-anchoring, result merging (60 s fixture-proven).
- Batch transcription (`transcribe_all`): scoped-thread worker pool over `Sync` backends (e.g. the mock backend), `concurrent_worker_count`-sized batches.
- Word timestamps: DTW over decoder alignment weights, duration constraints, punctuation merging (`DecodingOptions::word_timestamps`).
- Streaming: push-based `AudioStreamTranscriber` (VAD-gated, confirmed/unconfirmed segment promotion) and LocalAgreement-2 word confirmation (`LocalAgreementTranscriber`).
- Language detection; SRT/VTT/JSON result writers; `serde` and `tracing` optional features.
- Examples (`transcribe_wav`, `mic_stream`) and benches (criterion stage benches + an end-to-end RTF harness).
