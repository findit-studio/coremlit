# Changelog

Notable changes to the crates in this workspace. Versions follow SemVer per crate.

## coremlit 0.1.0 (unreleased)

Initial release: a safe, synchronous CoreML runtime layer.

- `Model`: load / compile / prewarm, synchronous `predict`, eager `ModelDescription` I/O snapshot.
- Stateful prediction via `MLState` (macOS 15+, probed at runtime with `supports_state`).
- `MultiArray`: typed views for `f16`/`f32`/`f64`/`i32`, IOSurface-backed `f16` construction for the Neural Engine, stride-aware `read_at`/`copy_into` for row-padded outputs, index math and scatter fills.
- `Features`: insertion-ordered named I/O bridging `MLFeatureProvider` in both directions (output extraction de-aliases buffers shared with inputs or other outputs).
- Threading: `Model`, `MultiArray`, and `State` are `Send` but deliberately **not** `Sync` — move them between threads or hold one per worker; concurrent shared access is outside the contract.
- `ComputeUnits`/`DataType` vocabularies; structured `thiserror` errors capturing `NSError` domain/code/message.
- `audio::speaker::extract::Extractor::extract_chunk_embeddings` (feature `speaker`): the per-chunk EMBED door, opening the middle node of the `segmentation → embed → cluster` split whose other two ends (`SegmentModel::infer` + `multilabel` + the `window` grid; `count_from_segmentations` + `Extraction::try_from_parts`) were already public. One chunk's audio and its `[f][s]` multilabel slab in; that chunk's `[s][d]` raw-embedding block out, with the slab zeroed in place along both drop paths — i.e. pyannote's `embedding_exclude_overlap` mask derivation, the batched embed call with its placeholder-mask scheme, and the per-row PLDA reachability check, none of which an out-of-crate embed node can write correctly by hand. Additive: `Extractor::extract` keeps its signature and its behaviour, and is now a caller of the same private `embed_chunk_slots` this door runs, so the fused path and the split path cannot drift on a policy this crate parity-gates against dia. Pinned by an equivalence gate that drives 30 s of `ted_60` through the public doors chunk by chunk and rebuilds an `Extraction` BIT-identical (`f32::to_bits`/`f64::to_bits`, not `==`) to the fused `extract`'s. Takes no `SegmentModel` — the split exists so the embed node never loads one — and reads only `Options::window`'s `onset`; the chunk must be exactly `SEG_CHUNK_SAMPLES`, refused with the segmenter's own `InferError::InputLength` rather than padded, because `EmbedModel::embed_chunk` repeat-pads where `extract` zero-pads.
- `audio::speaker::calibrate` (feature `speaker`): the AS-Norm calibration surface (#123 ask 2) — the crate's FIRST **cross-recording** speaker door, and the answer to "raw cosine scores are not comparable across speakers, so a single global threshold over-merges some identities and under-merges others". Everything else in `audio::speaker` is within-recording; this one scores voice profiles at cluster-centroid grain against a library-wide cohort, for binding the same person found in two different recordings. `coremlit` exposes SCORING and never a store: the caller owns the library, the identities and the cohort-selection policy. The AS-Norm1 arithmetic is `diaric::score_norm` CALLED THROUGH, not reimplemented — the `AsNormOptions` defaults and the `MAX_NORMALIZED_ERROR` accuracy postcondition are re-exported so a caller needs no direct `diaric` dependency to configure it, while diaric's containers and its free `as_norm` deliberately are not: a re-exported generic `Cohort<K, T>` carries a public `stats_excluding` and `T` is unconstrained, so a caller holding the exact `VoiceProfile` these doors produce could reach an unbound, candidate-dependent statistic through coremlit's own surface. **A calibrated trial is the product of ONE scoped operation.** `Calibration::new(cohort, options)` fixes an impostor population and a configuration together under an opaque, unforgeable `CalibrationId`; `enrolled_side`/`side` produce a `TrialSide` bound to its own profile; `trial(&a, &b)` returns a `CalibratedTrial` carrying the raw similarity AND the AS-Norm score. eq. (7) has four things that must agree and the caller now assembles none of them: the METRIC (a side exists only if its profile matched every cohort entry it was scored against, and the trial's raw score is computed from those same two profiles), the COHORT (owned by the calibration, by value, so it cannot grow under a side already taken), the ENDPOINTS (`trial` is handed no score — it computes one from the two sides' own profiles), and the CONFIGURATION (owned by the calibration too). That shape replaces three loose values — a raw score and two statistics — which three rounds of review each bound one more attribute onto while the next one stayed unbound; the residual is stated rather than claimed away, and it is one check over one identity: two calibrations are two values, so a side of one handed to the other is `CalibrateError::CalibrationMismatch` (naming all three identities) rather than a compile error, which would take an invariant lifetime and a closure-scoped API and would end the reuse guarantee. **The two sides of a trial are not symmetric, and the surface says so.** An ENROLLED speaker has an identity the caller can name, so `enrolled_side` drops that speaker's own entries from a library-sampled cohort — and it takes ONE `Enrolled` value binding an identity to the profile, so no second argument is left that could name a different speaker. That identity is a `SpeakerToken` the COHORT minted, not a borrow of the caller's key: `Eq` does not forbid interior mutability, so an `Rc<Cell<u64>>` key — `Eq`, and writable through a handle the caller keeps — re-decided what a side excluded between two derivations while the `CalibrationId` did not move, and `trial` then averaged a clean side with a self-contaminated one and returned a finite number. `LibraryCohort::token` is now the one place `K` is ever compared and it takes `&mut self`, so every exclusion set is fixed before the calibration exists (a calibration lends its cohort out shared, pinned by an `E0596` doctest); a token from another cohort is `CalibrateError::ForeignSpeaker` rather than an exclusion of nothing. An unidentified PROBE has no such key: its identity is what identification is trying to DISCOVER, so it scores against a keyless `HeldOutCohort`, whose single named constructor `assuming_disjoint` is the one place the caller states the provenance fact ("these profiles are nobody in my library") that they *can* answer without knowing who the probe is. Excluding the CANDIDATE's key from a probe's side — which the first draft of this surface recommended in its docs, its runnable example and its tests, and which diaric's own `stats_excluding` names as a failure verbatim — drops a valid impostor and makes the probe's statistics candidate-dependent: on a three-member cohort where the probe scores `[0, 0.8, 0.2]`, dropping the candidate that scored `0.8` moves the normalized trial from 1.641 to 4.455, across any threshold between them. Repairing that also makes the published reuse guarantee TRUE, which under the old guidance it was not: a side depends on its own profile and its own calibration and on nothing else, so N enrolled speakers against M probes over a cohort of C costs `(N + M)·C` cohort scores rather than `N·M·C`. Where it does not hold is stated rather than hidden — a probe against a library-sampled cohort has no entrypoint, because it has no correct statistic. **No cohort statistic leaves the module — not by an accessor, not by a `Debug`, and not by a refusal.** A `TrialSide` publishes neither μ nor σ, has no accessor to the `CohortStats` inside it, and its `Debug` is hand-written because the derived one printed both; `VoiceProfile::score` is private, so a raw similarity reaches a caller only inside a `CalibratedTrial` a calibration produced. The REFUSAL path is closed too, and it needed no `TrialSide` to exist: `diaric`'s `DegenerateDeviation` carries the exact σ that failed the floor and its `ZScoreCancellation` carries both z-scores and the value they cancelled to, so a `min_deviation` raised above what a perfectly valid cohort spreads handed back an operand the success path withholds. `CalibrateError::ScoreNorm` now carries `ScoreNormRefusal`, coremlit's own one-per-category re-statement: the floor that was breached, and how many scores were selected out of how many considered (`CohortSelection`), and no `f64` at all — a property held by the type rather than by a check per variant, since `ScoreNormRefusal` derives `Eq` and `Hash` and an `f64` field at any depth makes both underivable. That is a correction: the version that shipped published `TrialScore::raw`, `SideStats::mean` and `SideStats::deviation` — every operand of `0.5·((s−μₐ)/σₐ + (s−μᵦ)/σᵦ)` — so the cross-cohort normalization the door refuses was a two-line function over values coremlit itself handed out. The claim the docs now make is the narrower one that is true: cross-cohort normalization is NOT structurally unavailable and cannot be made so, because a caller owns the embedding rows and `diaric` is a published crate; what is true is the narrower, enumerable claim that no cohort statistic coremlit computes — μ or σ, and there are only those two — reaches a caller by any door, refusals included, so that road starts with building the statistic rather than reading one off something this crate returned. It is deliberately not the broader "no operand escapes", for a reason now stated once with its closed form instead of being left for a later round to rediscover: `CalibratedTrial::raw` is eq. (7)'s `s` and is published on purpose, because #123's comparison is between the raw scores and the calibrated ones — and publishing a score alongside its normalization publishes the affine map between them, which DETERMINES the statistics behind it. Writing `aᵢ = 1/σᵢ` and `bᵢ = −μᵢ/σᵢ`, a side trialled against itself gives `c(i,i) = aᵢ·s(i,i) + bᵢ` and eliminates every `bᵢ`, so three sides of one calibration leave three linear equations in three unknowns and the solve returns each side's σ and μ to the last few digits — from `raw` and `calibrated` alone, with no accessor, no `Debug` and no refusal involved. A test carries that out and checks it against the private field. Nothing short of withholding one of the two published numbers closes it, and that would end the comparison the door exists for; what the claim is worth is that every door which HANDED a statistic over is shut, and shut uniformly, so a caller who wants μ and σ must solve for them rather than read them. **The metric refusals shrank with the shape**: `CalibrateError::NormalizationMismatch` is gone (the last step reads profiles again, so a three-way tag comparison has nothing left to compare) and `CohortMismatch` became `CalibrationMismatch`, since a cohort identity and an options set are one calibration's. `ScoringMismatch` stays, reported ahead of diaric's own `NonFiniteScore`, so a cohort holding one foreign entry is refused rather than averaged. **Two score sources**, both cosines, differing in the space: `Scoring::Cosine` calls `diaric::embed::cosine_similarity` so a trial's raw score is BIT-identical to what the online clusterer matches on (and to what the offline pipeline's `ahc_init` cuts on, whose Euclidean distance over L2-normalized rows is `sqrt(2 - 2*cos)`); `Scoring::PldaCosine` scores in the frozen community-1 128-d PLDA projection. The second carries a stated honesty boundary — the offline pipeline hands those features to VBx, a set-level EM that emits no trial score, so pairwise cosine in PLDA space is THIS door's construction, characterized and not validated, offered because #123's ask 3 is a comparison between score sources and needs more than one. NOT wired into the clustering path (that is within-recording, differently gated) and NOT a threshold — #123's ask 3 produces one, and it needs data this repository does not have. 35 hermetic unit tests over hand-placed unit vectors (was 27), ten error-payload tests (was seven), and thirteen doctests (was seven): a runnable end-to-end example plus twelve `compile_fail` pins with pinned error codes — a non-`Eq` speaker key cannot reach the cohort at all (`E0599`), a cohort inside a calibration cannot mint a token (`E0596`), and a bare `VoiceProfile` (which is exactly what an unidentified probe is) cannot reach the enrolled door (`E0308`); no `stats_excluding` resolves on a coremlit cohort; the three fields holding a diaric statistic or the container behind one are each pinned private on their own, since one shared pin would survive any single one of them going public; `mean` and `deviation` are pinned absent one at a time, for the same reason; `VoiceProfile::score` is pinned private; and neither `TrialSide` nor `CalibratedTrial` can be assembled by hand. Written red first — the three round-3 falsifiers failed on assertions reading `Ok(2.1344341807837393)` for a foreign speaker's statistics against A's trial score (A's own is 2.216988, and a threshold of 2.18 separates them), `Ok(2.083333315120804)` for two sides derived under different `top_n`, and a `Debug` line printing `mean` and `deviation` in full — and each survivor checked by mutation: a `trial` without the calibration check, one that checks only the enrolment side, one that computes the raw score from a single side, a constant `CalibrationId::mint`, side constructors that ignore the calibration's options, an enrolled door that excludes nothing, a derived `Debug`, a returning `mean` accessor, and a public `score` are each caught by named tests and nothing else. Round 4's two are pinned the same way — an `enrolled_side` without the foreign-token check, a `token` that never dedupes, a constant `SpeakerToken::mint`, a translation that collapses two refusal categories, and a bridge that never counts `considered` each fail named tests only — while putting an `f64` back into the payload is not a test failure but a COMPILE error, from the `Eq + Hash` derive. Among them the #123 claim made falsifiable: a fixture where no single RAW threshold separates a genuine trial for an isolated speaker from an impostor trial for a crowded one, and an AS-Norm threshold does.
- `embeddings::siglip` (feature `siglip`): SigLIP 2 (`siglip2-base-patch16-naflex`) image+text embeddings into a shared 768-dim joint space — NaFlex host-side preprocessing (aspect-preserving patch-budget solver, antialiased-bilinear resize, position-embedding lift; no image-decoder dep), a single-input 64-token text tower, and cross-modal `rank`, L2-normalized in Rust; committed transformers-fp32 goldens (no `ort`). - `audio::ced` (feature `ced`): CED (tiny/mini/small/base) AudioSet sound-event tagging — 16 kHz mono waveform in, ranked predictions over the 527 rated AudioSet classes out (`soundevents-dataset`, ort-free). Rust log-mel front-end (believed CED numerics, structurally gated; probe-pinned next wave) around one fp16 mel→logits graph; long clips via `windit` window geometry + Mean/Max confidence-space aggregation (soundevents semantics, tie-break pinned), bounded by a default-on `WindowPlan::max_windows` cap that refuses a window-count blow-up in O(1) with a typed `TooManyWindows`/`AllocFailed` before any span or inference is materialized (an untrusted `hop_samples: 1` is a typed refusal, not a panic/OOM) and streamed through a shared accumulator so `classify_long` never holds every window's confidences at once; `raw_scores` logit escape hatch; `DEFAULT_COMPUTE = All` documented PROVISIONAL. Hermetic core landed; per-size model-gated parity/e2e gates and goldens are pre-shaped and await each size's staged conversion.
- `audio::lid` (feature `lid`): native spoken-language identification — 16 kHz mono waveform in, the top `k` of a 107-language roster out (code + English name + model column + natural-log probability). A Rust log-mel front end (`rustfft`) feeds one fp16 mel→log-probabilities graph; the graph's last op is a log-softmax, so no softmax runs in Rust. Deliberately a **backend-neutral door**: nothing in the public surface (`Identifier`, `LanguageScore`, `Language`, the geometry constants, the `LID_TEST_MODELS` env var, the `Models/lid` root) names the model behind it, so a second backend lands without renaming a caller's code; today's backend is an Apache-2.0 CoreML export of `speechbrain/lang-id-voxlingua107-ecapa`. The 107-label roster is a COMMITTED in-crate asset (`include_bytes!`) with a `const` table proven byte-equal to it, preserving upstream's legacy `iw`/`jw` codes so no output column ever shifts (alias folding is a downstream job, and the three facts are pinned). One prediction is capped at 0.09–30.01 s, with anything outside it a typed `FrameCountOutOfRange` refused before CoreML sees it; `identify_long` lifts the ceiling by windowing, keeping `identify`'s contract byte-identical and returning bit-identical results on a clip that already fits one window. The two things a long path has to invent were MEASURED, on two oracles built from the model itself (self-consistency against the single-shot answer, and concatenation of the committed Thai reference), not assumed: window GEOMETRY rides `windit` (fixed 10 s default window — the one frame count `prewarm` warms — a `TailPolicy` that slides the final window BACK to full length rather than padding it, and the same default-on `max_windows` O(1) refusal `ced` carries), while log-probability POOLING is this door's own third domain, neither `ced`'s independent sigmoids nor windit's unit vectors. `ScorePooling` ships all four evaluated candidates — the duration-weighted logarithmic pool (default; best top-1, top-3 and row error at every geometry tried), the linear pool (keeps a mixed clip's minority language, which the default erases), per-class max, and a per-window argmax vote (rejected as default on 36–40 % top-3 agreement) — and the module docs carry the full comparison table, the tail-treatment numbers (zero-padding a tail of 3 s or less CHANGES the reported language, shifting the row by up to 19 nats, which is why there is no `Pad` policy), and an explicit list of what two model-derived oracles do not verify. ## whisperkit 0.1.0 (unreleased)

Initial release: a Rust port of [WhisperKit](https://github.com/argmaxinc/WhisperKit) (Swift) on CoreML, sans-I/O (16 kHz mono `&[f32]` in).

- Full pipeline: mel → encoder → autoregressive decoder with prefill prompts, KV caching, logits filters, and the temperature-fallback ladder; token parity with Swift `whisperkit-cli` on `openai_whisper-tiny` (en + es goldens).
- Long-form: energy-VAD chunking (sequential per chunk on the CoreML backend, which is deliberately not `Sync`), seek re-anchoring, result merging (60 s fixture-proven).
- Batch transcription (`transcribe_all`): scoped-thread worker pool over `Sync` backends (e.g. the mock backend), `concurrent_worker_count`-sized batches.
- Word timestamps: DTW over decoder alignment weights, duration constraints, punctuation merging (`DecodingOptions::word_timestamps`).
- Streaming: push-based `AudioStreamTranscriber` (VAD-gated, confirmed/unconfirmed segment promotion) and LocalAgreement-2 word confirmation (`LocalAgreementTranscriber`).
- Language detection; SRT/VTT/JSON result writers; `serde` and `tracing` optional features.
- Examples (`transcribe_wav`, `mic_stream`) and benches (criterion stage benches + an end-to-end RTF harness).
